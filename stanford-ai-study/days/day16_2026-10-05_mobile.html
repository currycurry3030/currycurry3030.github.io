🧩 핵심 개념

Retry policy

transient error만 제한적으로 재시도하고 backoff/max attempts를 둔다.

Idempotency

같은 요청을 반복해도 최종 상태가 한 번 수행한 것과 같게 만든다.

Validation

type/range/business rule을 실행 전에 검사한다.

Permission boundary

tool별 read/write·데이터·command 권한을 최소화한다.

🧭 Mental Model

call → validate → authorize → execute → classify error → retry/repair/stop

실무 연결: DB tool은 estimate → summarize → sample → expand only if necessary 원칙과 row/byte/time limit을 둔다. read-only 기본, retry 가능한 오류만 재시도하고 대량 결과 반환을 막는다.

주의: validation/permission error를 같은 입력으로 무한 retry하면 안 된다.
