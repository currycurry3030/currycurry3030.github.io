🧠 Active Recall

Q1. Benchmark와 metric의 차이는?
Benchmark는 시험 문제/과제, metric은 그 출력을 점수화하는 규칙.
Q2. Static benchmark가 오래되면 생기는 문제는?
포화, contamination, benchmark-specific overfitting으로 변별력이 떨어진다.
Q3. Spurious bias란?
목표 능력과 인과적으로 무관하지만 모델이 shortcut으로 이용할 수 있는 데이터 패턴.
Q4. Long-form 평가가 어려운 이유는?
좋은 답이 여러 개이고 correctness 외 coverage·coherence·factuality 등 여러 차원이 있기 때문.
Q5. LLM judge의 위험 두 가지는?
verbosity/position/self-preference 같은 bias와 judge 자체의 오류.
Q6. Goodhart’s Law가 왜 중요한가?
proxy metric을 직접 최적화할수록 실제 사용자 가치와 점수가 분리될 수 있어서.
Q7. Contamination을 exact duplicate만 검사하면 왜 부족한가?
paraphrase나 solution trace 같은 semantic near-duplicate가 남을 수 있어서.
Q8. 평가 재현성을 위해 score 외 무엇을 저장하나?
prompt, shots, decoder, parser, model version, evaluator/rubric 등 protocol 전체.

⚡ 10줄 치트시트

  1. WHAT = Benchmark / HOW = Metric
  2. 좋은 benchmark = scale/diversity + difficulty + quality + 낮은 shortcut
  3. Static의 약점 = saturation + contamination
  4. Dynamic/Adversarial = 실패를 능동적으로 갱신
  5. Open-ended일수록 평가 차원이 늘어남
  6. Classical overlap ≠ semantic/factual correctness
  7. Human도 noisy → rubric/calibration
  8. LLM Judge도 noisy → multi-judge/audit
  9. Goodhart → 단일 metric 금지
  10. Prompt/decoder/parser까지 versioning
