🧪 Deep Dive · Recipe Advisor의 Long-horizon Success

‘추천 문장을 생성했는가?’가 아니라 아래 chain이 끝까지 성립하는지 평가.

1. Current context를 충분히 확보2. 적용 가능한 Evaluation Case를 retrieval3. 근거와 applicability를 확인4. 여러 Δrecipe/DOE candidate 생성5. Δmetric / constraint / uncertainty 예측6. OOD/위험 candidate reject 또는 abstain7. evidence/provenance가 붙은 Top-k 제공8. engineer가 검토 가능한 형태로 종료
Failure taxonomy예
Context failure필수 Recipe/Metrology 조건 누락
Retrieval failure유사하지만 적용 불가능한 Case 선택
Query failure대량 결과/truncation/잘못된 집계
Prediction failureΔmetric 방향/크기 오류, calibration 불량
Safety failureconstraint/OOD를 놓침
Grounding failure근거 없는 rationale 또는 provenance mismatch
Human-interface failure엔지니어가 판단하기 어려운 출력

🎯 오늘의 목표

  • 짧은 QA accuracy가 아닌 긴 작업의 success rate, pass@k, failure taxonomy.
  • 핵심 용어 4개를 한국어로 설명한다.
  • Recipe Advisor용 success criteria + failure taxonomy 완성.

🧩 핵심 개념

Task success rate

전체 목표를 끝까지 충족한 run의 비율이다.

pass@k

k번 시도 중 최소 한 번 성공할 가능성을 보는 지표다.

Partial credit

subgoal·evidence coverage·tool correctness 같은 중간 성과를 점수화한다.

Failure taxonomy

planning/tool/retrieval/reasoning/verification/timeout 등 실패 원인을 분류한다.

🧭 Mental Model

define success → define subgoals → run seeds → score → tag failure → aggregate

실무 연결: Long-horizon success는 ‘추천 문장 생성’이 아니라 올바른 context 확보 → 근거 있는 candidate → constraint pass → uncertainty 표시 → engineer가 검토 가능한 DOE안까지의 end-to-end 성공으로 정의한다.

주의: 부분 metric을 목표로 과최적화하면 실제 end-to-end 성공과 분리될 수 있다.
